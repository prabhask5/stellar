# Decisions

One line of context, the choice, and why. Newest at the bottom of each phase.

## Phase 0 — Scaffold

- **TypeScript version.** TypeScript 7 is the latest release, but `typescript-eslint` only supports `<6.1`. → Pinned TypeScript `~6.0`. Linting with type-aware tooling matters more than the newest compiler.
- **Package manager.** pnpm 12 via Corepack (`packageManager` field). Native build scripts are allow-listed in `pnpm-workspace.yaml`.
- **Internal packages ship TypeScript source.** `packages/*` export `./src/*.ts` directly and are transpiled by Next (`transpilePackages`) and Vite (WXT). No per-package build step, so edits are instant and there is one compiler configuration.
- **Token outputs are committed.** `packages/ui-tokens/css/*.css` and `docs/ios/StellarTokens.swift` are generated by `pnpm tokens` and checked in; a unit test fails when they drift from `tokens.json`. Builds never depend on a generation step.
- **Tailwind names.** `text.primary`/`text.secondary` map to `fg`/`fg-2`, `bg.void` to `void`, `glass.border` to `hairline`, so utilities read naturally (`text-fg-2`, `border-hairline`).
- **Safe-area variables.** Components read `--sat/--sar/--sab/--sal`, which are defined only as `env(safe-area-inset-*)`. Tests simulate a notch or Dynamic Island by adding a class to `<html>` (SPEC §9.1 allows a test-only class). No inset value is hardcoded in components.
- **CSS starfield.** Stars are seeded radial-gradient tiles rendered by a server component: zero client JS, identical on every device, part of first paint.
- **Playwright runs against the standalone build** (the same artefact the Docker image runs), with Chromium using iPhone device descriptors for the phone projects. WebKit is not required to run the suite.

## Phase 1 — Database

- **Local test stack.** SQL parity tests and e2e need a real Supabase. `dev/supabase/docker-compose.yml` runs a lean compatible stack (Postgres 15 + GoTrue + PostgREST + Realtime + pg-meta behind an nginx gateway on :54321) instead of the full Supabase distribution: same APIs, a fraction of the disk and start-up time. Dev-only keys live in `dev/supabase/dev.env`.
- **Idempotent migrations.** Every migration is written so it can be re-run (`create … if not exists`, `create or replace`, `drop … if exists`). That makes the paste-into-Studio fallback safe to run twice and lets the runner, the pg-meta path and the pasted script share one SQL source. SQL is embedded in `bundle.generated.ts` so the standalone server never reads migration files at runtime.
- **`sort_order` is `double precision`.** Reorders write one row with the midpoint of its neighbours; `sp_rebalance` respaces a list when a gap is exhausted. Chosen over text keys because inserts without a rank (API clients) get one from a one-line trigger, and ordering has no collation pitfalls.
- **Timer extras.** `sp_focus_state` adds `phase_total_ms` (the planned length, fixed when a phase starts, so every device draws the same ring even if settings change mid-phase) and `last_completed_phase` / `last_completed_at`. The scheduler compares `last_completed_at` with `notified_phase_end_at` to send each phase-end push exactly once, whichever device advanced the timer.
- **Timer semantics where the spec is silent.** After a long break the round resets to 1. `skip` follows the same auto-start rule as a natural phase end. An advancer up to 10s late starts the next phase exactly at the boundary (no drift); later than that, from "now" (no stale catch-up chain after downtime). `end` and `skip` record an abandoned phase with the time actually spent.
- **Timer state is written only by RPC.** `sp_focus_state` and `sp_focus_sessions` are select-only for the owner; `sp_timer_action` (security definer) is the single writer, so the version check cannot be bypassed.
- **Ledger rule.** Only un-completing something appends negative points. Structural changes (deleting a task, list or routine, rewriting a routine) never touch the ledger: earned stardust is permanent (pillar 3). Two derived awards are reconciled as state: "goal list 100%" and "routine day 100%" are reversed when the state stops being true and are never awarded twice.
- **Goal progress points telescope.** Points are `round(50·new) − round(50·old)`, so one hundred 1% steps earn exactly the same 50 as one jump.
- **Routines hard-delete; tombstones cover delta sync.** Deleting a routine removes its logs (spec). Hard deletes (routines, logs, block sites, quotes) write `sp_tombstones` so `updated_since` can report removed ids. `sp_routines.deleted_at` exists per the spec but is unused. Task/goal/block lists and tasks/goals soft-delete; deleting a list soft-deletes its children with the same timestamp so Undo restores exactly those.
- **Clients compute, Postgres decides.** The web app keeps routines + logs in its cache and uses the shared TypeScript functions for instant rings and streaks; the SQL twins (`sp_routine_days`, `sp_routine_streak`, `sp__scheduled`) serve the API and are held to the same fixtures.
- **Era numbering.** Eras are shown one-based ("Era III · Nebula"), matching the mockup.
- **Quotes.** 132 built-ins, all from authors or translations in the public domain, attributed; commonly misattributed lines were left out.
- **Streak definition.** Consecutive _scheduled_ days completed, counting back from today; an unfinished today does not break the streak, a missed previous scheduled day does.

## Phase 2 — Setup & auth

- **Web session model.** The spec wants httpOnly cookies _and_ direct browser-to-Supabase access. The refresh token lives only in httpOnly cookies (`@supabase/ssr`, cookie name `sp-auth`). The page asks `GET /api/v1/auth/session` for a short-lived access token, keeps it in memory, and uses it for PostgREST and Realtime. Page scripts can never read the long-lived credential, and the PIN endpoint returns no tokens to web clients.
- **Session checks.** The proxy only checks that the session cookie exists (no network on navigation; pages are static shells and RLS guards the data). `/auth/session` verifies the token with the auth server, so "sign out everywhere" and device revocation end other browsers at their next token fetch. An access token already in memory stays valid until it expires (at most one hour); that is inherent to JWTs.
- **Owner only.** The API accepts tokens only for the hidden owner's user id, because the Supabase project may host other users.
- **Lockout is global, not per IP.** There is one owner, so 5 wrong PINs lock sign-in for everyone (30s, doubling, 1h cap, persisted in `/data/lockout.json`; a corrupt file fails closed). A separate in-memory per-IP limiter throttles the auth and setup endpoints.
- **PIN length is never disclosed.** The lock screen shows an Unlock button; after one successful sign-in the device remembers the length locally and auto-submits from then on.
- **Setup endpoints close after first run.** Connect/migrate/verify are open only until setup first completes; afterwards they require a session (Settings → Connection). `RESET_PIN=true` reopens only the PIN step and re-keys the hidden owner, which signs out every device. The PIN is cleared on every boot while the variable is set; the UI and docs say to remove it.
- **Service-role probe.** Checked by fetching a non-existent user id through the admin API (404 = key works) instead of listing users, which is both cheaper and immune to foreign rows that GoTrue cannot scan.
- **VAPID keys** are generated with Node's `crypto` (P-256), with no dependency in the setup path.
- **Data directory.** `/data` in the container, `STELLAR_DATA_DIR` to override, `.data/` beside the app in local development.
- **Migrations on boot** run only when a Postgres connection string is configured; otherwise Settings → Connection offers the paste-and-verify path after an update.
- **E2E isolation.** Tests reset the instance by deleting the files in the test data directory and the owner user, and send a unique `X-Forwarded-For` per test so the rate limiter needs no test-only switch.

## Phase 3 — App shell & design system

- **One cached collection per table.** Each table is a TanStack Query entry holding an array; views (Today, All, Calendar, lists, day rings, streaks) are pure functions from `packages/shared` over those arrays. Realtime patches the arrays by id. Tasks load open tasks plus those completed in the last 90 days; routine logs load the last 400 days.
- **Every write goes through the outbox.** A mutation updates the cache first, then queues an operation (IndexedDB-backed, sent strictly in order). Inserts carry client-generated ids and are sent as "insert or ignore"; updates that waited more than 15 seconds are guarded by `updated_at` so an offline edit cannot overwrite a newer change (last write wins). A rejected operation is dropped, the affected collection is reloaded, and a toast says so.
- **Realtime echoes never fight the user.** While a row has operations queued, incoming Realtime rows for it are ignored; when the last operation settles, the server's version of the row replaces the optimistic one.
- **Realtime joins with the owner's token.** The socket is authenticated (`realtime.setAuth()`) before the channel subscribes, so RLS filters apply. One channel carries all ten tables plus presence (the "N devices in sync" count). Hard-delete tables get an extra unfiltered DELETE listener because delete events cannot be filtered by column.
- **Goal increments are deltas.** `sp_goal_increment` is sent with the delta, not the new total, so increments made offline on two devices add up.
- **Completion feel.** The checkbox fills immediately; the row lingers 600ms, then leaves; consecutive completions share one Undo toast ("3 tasks completed").
- **Routes are static shells.** List detail uses a query parameter (`/tasks?list=…`) rather than a dynamic segment so every page can be precached for offline use.
- **Command bar ordering.** Typed text that matches a command ranks that command first; "Add task “…”" is always offered last (and is the only result for ordinary task text).
- **Emoji data is self-hosted** under `/emoji` (copied from `emojibase-data`), so the picker makes no third-party requests and works offline. Refresh with `node apps/web/scripts/copy-emoji.mjs`.
- **Sidebar wording** follows the mockup: "716 stars to Star Cluster" (the number is stardust still needed for the next era).
- **Dev stack Postgres.** The test stack builds Postgres 15 with `wal2json` and allow-lists it in `output_plugin_libraries` (required by current Postgres releases) so Realtime works locally.

## Phases 4–6 — Tasks, Goals, Routines

- **Quick add defaults.** On the Today tab a new task is due today, on Calendar it takes the selected day, on All it has no date. Otherwise a task added from Today would vanish from the view it was added in.
- **Task lists on phones** are their own segment ("Lists"); on desktop they sit in the right column as in the mockup.
- **"Show completed" is per view and per device** (localStorage). All and list views show what is in the cache (completed within 90 days); Calendar loads older completed tasks for the visible range on demand.
- **Reordering** is available for task lists, goal lists, goals, and tasks inside a list (drag handle, long-press on touch, keyboard). A drop writes one row; `sp_rebalance` runs only when a gap is exhausted.
- **Swipe actions** exist only on touch devices: right completes, left reveals Reschedule and Delete.
- **Goal amounts.** The stepper is −/+ as in the mockup; the current number in "5 / 8 glasses" is itself the tap-to-type control. Holding − or + repeats.
- **Routines: today is always inline on phones** (as in the mockup); tapping another day opens that day in a sheet. Desktop shows the selected day inline beside the calendar. Future days show the schedule read-only.
- **Manage routines** expands in place from the mockup's "Manage routines · N active" row.
- **Tab bar fill** is slightly more opaque than `glass.fill` because Chromium does not blur content that sits inside another backdrop-filtered card; legibility must not depend on the blur.

## Phase 7 — Focus

- **Who advances the timer.** The server's scheduler loop (every 2s, single instance per process, started from `instrumentation.ts`) is authoritative. Each open client also schedules a fallback `advance` 2.5s after the phase should have ended; the versioned RPC makes that race harmless. The loop also runs the daily purge of soft-deleted rows.
- **Optimistic timer.** Controls apply the shared state machine locally (instant), then send the action with the version it was based on. A conflict simply replaces the optimistic state with the server's.
- **Phase strip is a display**, not a control: phases change only through the timer (Start, Skip, End), which keeps every device on the same path.
- **Settings changes apply from the next phase**; the running phase keeps the length it started with (`phase_total_ms`).
- **Space on Focus** starts, pauses or resumes unless a button, field or dialog has the keyboard.
- **Fullscreen** is an in-page overlay that also requests the Fullscreen API where it exists (iPhone has none), so it works everywhere.
- **Block list sites.** Entries are split on whitespace, commas and new lines, so pasted lists work; valid ones are added immediately and only the entries that need fixing stay in the box with a message.
- **Push.** Sent by the scheduler for phases completed by anyone (server or client), exactly once, and skipped if the phase ended more than 10 minutes ago (after downtime). Dead subscriptions (404/410) are removed. Permission is requested only from a button.
- **Stats** come from `sp_focus_stats` (owner time zone); the phase in flight is added client-side so today's total moves while you focus. All focus time counts, including phases ended early; stardust is awarded only for completed focus phases.

## Phase 8 — Universe & events

- **Two layers.** The persistent universe is a WebGL scene behind the interface (React Three Fiber `Canvas`, scene built imperatively in `scene-core.ts`). Cosmic events paint on a separate 2D canvas above the interface with `pointer-events: none`. Events therefore work on every tier, never need a second WebGL context, and cost nothing while idle (the overlay's animation loop stops when no effect is alive).
- **No React in the hot path.** The app writes to a vanilla zustand store (`universeStore`); the canvas subscribes and updates buffers and uniforms. The host is mounted once in the root layout and re-renders only when the tier changes, so navigation never touches it.
- **Loading.** The CSS starfield is server-rendered. `three`, R3F and postprocessing are imported with `import()` from an idle callback, only when signed in and the tier is not Minimal; the canvas fades in once it has drawn a frame.
- **Own render loop.** `frameloop="never"` with a requestAnimationFrame loop that pauses when hidden or while typing on a phone, throttles to the tier's idle frame rate, and feeds a `FrameGovernor` (3s above budget → step down a tier).
- **GPU tier without a CDN.** `detect-gpu` downloads benchmark data from a third party at runtime, so the tier comes from a local classification of the WebGL renderer string plus memory, cores, data saver and battery. An explicit setting is honoured wherever WebGL exists; Auto falls to Minimal on software rendering, reduced motion or data saver.
- **Deterministic sky.** Stars, systems, planets and constellations are placed by hashing their ids (`layout.ts`). Recent stars use task ids; older ones use "month:n" seeds from the snapshot's monthly counts, so tens of thousands of stars need no rows.
- **Camera.** The view is offset (`setViewOffset`) so the core sits in the free space of each layout (above the Today card, right of the sidebar). The Universe home's open area takes drag, pinch and wheel; the camera eases back about a second after release. Hover/tap labels come from projecting planets and constellations to screen space a few times a second.
- **Ledger-true counts.** "N stars ignited" and star seeds come from the ledger, so stars from tasks that were later deleted or purged remain.
- **Coalescing.** Same-kind events inside a three-second window merge into the running effect (more sparks, a bigger flare). The large cinematic events (new Era, First Light, supernova, system blossom) play one after another rather than on top of each other.
- **New Era detection** happens on the device: a snapshot whose era index is higher than the last one seen triggers the cinematic. The Era name is real text (`role="status"`), not canvas pixels.
- **Reduced motion and Minimal.** Every event becomes a soft glow under half a second; the sky is the static CSS starfield with its drift and twinkle animations off.
- **Diagnostics.** `window.__stellarUniverse` exposes the scene's hover targets and core position (read-only data) for debugging and tests.

## Phase 9 — PWA & offline

- **Service worker tooling.** The worker is written against Serwist's runtime (`serwist`) and built by `scripts/build-sw.mjs`: esbuild bundles `sw/sw.ts`, then `@serwist/build` injects the precache manifest (every hashed file in `.next/static`, icons, emoji data). This runs after `next build` and works with Turbopack without a bundler plugin.
- **Pages are stale-while-revalidate, keyed by path.** A cached open is served from the device immediately and refreshed in the background, which gives the instant shell and makes updates arrive through the "New version available, Reload" toast. After activation the worker fetches every app route once, so routes never visited still open offline. `/api`, `/setup` and `/lock` always use the network.
- **No data in the service worker.** API and Supabase responses are never cached by the worker. Data lives in the persisted TanStack Query cache (IndexedDB), writes in the outbox; signing out deletes both.
- **Update flow.** The new worker waits; "Reload" posts `SKIP_WAITING` and the page reloads once on `controllerchange`. Updates are checked when the app returns to the foreground and hourly.
- **Splash screens and icons** are generated by `pnpm --filter @stellar/web pwa:assets` (sharp) from `apps/web/assets/icon.svg` and committed, so image tooling is not needed at build time. Thirteen iPhone portrait sizes are covered.
- **Install hint.** Shown only in iOS Safari outside the installed app, on the Universe home, and never again after it is dismissed.
- **Manifest shortcuts** open `/tasks?new=1` (cursor in quick add) and `/focus?start=1` (starts or resumes the timer).
- **Outbox race fixed.** Unit tests showed two flushes could start at once and send an operation twice; the flush now claims itself synchronously.
- **Device matrix.** One spec walks every page at the eight SPEC §9.1 sizes with simulated insets and asserts: no horizontal overflow, nothing clipped, headers below the top inset, tab bar above the home indicator and inside side insets, background full-bleed.

## Phase 10 — Extension

- **Host access.** A declarativeNetRequest _redirect_ only applies to requests the extension has host permission for, so the manifest declares `host_permissions: ["<all_urls>"]` (any site may be put on a block list from another device). The same grant lets the background reach the instance and Supabase. Chrome grants it at install; Firefox treats MV3 host permissions as optional, so the popup also calls `permissions.request` from the Continue click.
- **Rules use `regexFilter` + `regexSubstitution`,** not `urlFilter: "||domain^"`. The spec's block page must offer "continue to the originally requested URL", and only a regex substitution can carry that URL: the rule redirects to `blocked.html?site=<domain>#<original URL>` (the fragment needs no encoding). Each regex matches the domain and all subdomains over http/https, main frame only. Beyond 900 domains (Chrome allows 1,000 regex rules) the remaining ones fall back to `urlFilter` rules without the continue address.
- **The block page only ever links back to the blocked site itself:** the address in the fragment is ignored unless its host belongs to the blocked domain.
- **No state in memory.** Connection, session and the last snapshot live in `storage.local`. The worker re-syncs on install, browser start, a 30-second alarm (the shortest period browsers allow), `online`, popup/block-page open, and every Realtime event. An alarm at `phase_ends_at` lifts the block with no network; a paused focus phase blocks until a state change arrives.
- **One round trip.** The extension reads everything from `sp_focus_get` (state, settings, active lists, patterns, server time) and refetches on any change to the four tables, which keeps the background tiny and correct.
- **Realtime keep-alive.** The socket heartbeat is 20 seconds, under Chrome's 30-second service-worker idle limit, so an open socket keeps the worker alive while it is needed.
- **Presence.** The extension joins the same presence channel as the app, so it counts in "N devices in sync".
- **Firefox.** `browser_specific_settings.gecko.id` is `stellar-planner@stellar.local`, minimum version 128, with `data_collection_permissions: none` (the extension talks only to the owner's own instance).
- **Distribution.** `pnpm --filter @stellar/extension zip` builds both targets and copies `stellar-planner-chrome.zip` / `stellar-planner-firefox.zip` into `apps/web/public/extension/`; the web build depends on it, so the Docker image always serves matching packages.

## Phase 11 — API & iOS readiness

- **Thin facade.** Each handler forwards the caller's token to Supabase and lets RLS, constraints, triggers and RPCs decide. Shared plumbing is in `apps/web/lib/server/resource.ts` (list with delta sync, idempotent create, update, soft/hard delete, reorder). Postgres errors map to the envelope: check/validation → 400, missing → 404, permission → 403, unique → 409.
- **Delta sync.** `updated_since` returns changed rows plus `deleted_ids`, the union of soft-deleted rows and tombstones of hard deletes. Clients pass back the previous `server_time`.
- **Idempotent creates** use the client's `id` with insert-or-ignore, then return the stored row, so a retry never overwrites later edits.
- **`GET /tasks`** without `view` is the sync feed; with `view` it calls `sp_tasks_view`, the same ordering the app uses.
- **`POST /focus/actions`** answers `409` when the version check fails, with the normal body (`ok: false`, reason, current state), so clients can branch on status or body.
- **Extras beyond §11:** `/tasks/reorder`, `/goals/reorder`, `/routines/reorder`, `/block-lists/reorder` (the spec lists reorder only for lists, but every ordered collection needs it) and `/api/v1/openapi.json`.
- **`DELETE /quotes`** takes `?id=` (or `{ id }` in the body), as §11 lists it without a path parameter.
- **OpenAPI** is built in `packages/shared/src/openapi.ts` with zod 4's `z.toJSONSchema`; request schemas use input types, responses output types, and objects are left open so later fields are not breaking. Tests check `docs/openapi.json` is current, that every documented operation has a handler exporting that method, and that no route is undocumented.
- **Rate limits:** auth endpoints keep their strict per-IP limits and PIN lockout; everything else shares 1,200 requests a minute per session type.

## Phase 12 — Ship

- **Image.** `node:24-bookworm-slim` (current LTS, glibc so the prebuilt argon2 binary loads without a compiler), three stages (dependencies, build, runtime). The runtime stage contains only Next's standalone output, static assets and `public/` (including both extension zips, built in the same image). Runs as the unprivileged `node` user (uid 1000) with `/data` owned by it; `HEALTHCHECK` calls `/api/health` with Node's own `fetch`, so no curl is installed.
- **Performance budget, measured.** `pnpm budgets` reads the prerendered HTML of each route, sums the gzip size of every script the document requests (skipping the `nomodule` polyfill bundle, which supported browsers never download) and fails if three.js appears in any of them. The first measurement was 347 KB on the home route against the 200 KB budget, so the client was restructured:
  - zod no longer reaches the browser (`sideEffects: false` on `@stellar/shared` and `@stellar/db`, and the two client-side `parse` calls on our own RPC results became typed casts; validation stays on the server and in the database);
  - `@supabase/supabase-js` is imported on first use (`getSupabase()` is async), so cached data paints before the client library arrives;
  - Motion uses `LazyMotion` with `m.*` elements; the animation engine (`domMax`, `animate`) loads after the page is interactive;
  - sheets, the command bar and popovers are thin wrappers that fetch their Radix-based implementation when the browser is idle or on first open, whichever is first.
- **Budget scope.** The spec's budget is for "the first route". The check enforces 200 KB on the routes a visit starts on: `/` (also the PWA start URL), `/lock` and `/setup`. Home measures 199 KB, of which React and the Next runtime are 126 KB. The other pages are reached by client-side navigation that reuses the shell, and are held to a 230 KB ceiling when opened directly (they add drag-and-drop and their editors; the largest, Tasks, is 224 KB). This reading and the numbers are stated in the final summary rather than hidden.
- **Two e2e races fixed, not product bugs.** Home now mounts quickly enough to consume the one-shot "First Light" flag before the test could read it, so the test records the write instead; and the import test now targets the confirm button inside the dialog rather than "the last Import button on the page".
- **Sync cursor comes from the database (migration 0009).** The full e2e run caught `updated_since` missing a deletion: `server_time` was the app server's clock while tombstones are stamped by Postgres, and the two differed by a few milliseconds. `sp_now()` now supplies the cursor, read before the rows. Against a database that has not run 0009 yet the API steps the cursor back five seconds instead, which can only repeat a change, never lose one.
- **Swipe settle stays synchronous.** With the spring engine lazy-loaded, a task row preloads it on mount and calls it in the same frame as the gesture's release once loaded; only a swipe made before it arrives waits for it.
- **Small-screen polish found in the final screenshot review:** segmented controls and the focus phase strip size segments by content so "Calendar" and "Short break" are never cut off at 320px; the tab bar fill is 94% opaque so list text does not ghost through it; the home Tasks stat steps down a size for three-digit counts; a dangling separator dot in progress-goal rows was removed.
- **Disconnecting the extension leaves nothing behind.** The last full run caught a sync that was already in flight writing its status back to storage after Disconnect had cleared it. Disconnect now waits for that sync, and an unlinked background writes nothing.
- **Container check.** The built image was started with no environment variables: healthy, redirects to `/setup`, runs as uid 1000, serves both extension zips, the service worker and the OpenAPI document. Setup, PIN sign-in and API calls were then driven against it, and the configuration survived a restart through the `/data` volume.

## Polish pass 1

- **WebKit is now required.** This replaces the Phase 0 line "WebKit is not required to run the suite". `apps/web/playwright.config.ts` adds `webkit-iphone-15-pro`, `webkit-iphone-se` and `webkit-iphone-15-pro-landscape` (WebKit with the iPhone descriptors; the landscape project uses the installed app's full 852×393 screen) and `firefox-desktop`. The WebKit projects are the primary mobile target: every spec must pass on them. The three original Chromium projects stay so nothing regresses. Install the engines with `pnpm --filter @stellar/web exec playwright install webkit firefox`.
- **Phone layout vs touch in tests.** Landscape is 852px wide, so it gets the rail layout with touch input. Helpers therefore separate `isPhone` (tab bar and sheets) from `isTouch` (keypad, swipes, iOS user agent).
- **Touch swipes in WebKit and Firefox.** Playwright can only produce real touch drags in Chromium (DevTools protocol). For the other engines the `swipe` helper dispatches the pointer-event sequence a finger produces. That exercises our gesture code, not the browser's own touch handling, so real-finger behaviour stays on the iPhone checklist.
- **Audit specs are opt-in.** `apps/web/e2e/audit/*` (adversarial pass, axe/overflow/touch-target scan, perf and memory measurements) only run with `AUDIT=1`; they write to `docs/polish/data/`. With `AUDIT_LOG=<file>` every e2e page also logs console errors and warnings, uncaught errors, failed or 4xx/5xx requests and layout shift.
- **`scripts/seed-polish.mts`** fills the local instance with the POLISH_SPEC §1 data set. It refuses to run against anything but a loopback database. Older routine logs and focus sessions are inserted with scoring skipped so the total lands in Era III.
- **AUDIT.md is generated.** Findings live as data in `docs/polish/data/` (`static-findings.json` from code review, `dynamic-findings.json` from the runs, `audit-status.json` for statuses) and `node scripts/polish/build-audit.mjs` writes `docs/polish/AUDIT.md`, so two hundred entries keep stable ids and their statuses can be updated without hand-editing.
- **Official Supabase bundle.** `dev/supabase-official/` holds a Supabase CLI project (CLI 3.3.0, official Kong, GoTrue, PostgREST, Realtime and Postgres 17 images) on ports 553xx, so it runs beside the dev stack. `E2E_STACK_ENV`, `E2E_DATA_DIR` and `E2E_PORT` point the suite at it (see its README). The first attempt filled the machine's disk mid-pull and took Docker down; after the owner freed space it ran. The smoke subset (setup wizard, PIN, shell with two-tab Realtime, tasks, focus, extension) passes with no behaviour differing from the dev stack. The tests had three hard-coded ports, now derived from the environment.
- **Firefox extension is tested in a real Firefox.** Playwright cannot load extensions into Firefox, so `pnpm --filter @stellar/extension smoke:firefox` drives the built package with Selenium and geckodriver (install, host permission, connect errors, connect, rules and badge, redirect to the block page, countdown, handoff). WebDriver may not navigate to `moz-extension://` itself; the script loads extension pages through the browser's chrome context (`geckodriver --allow-system-access`) and pins the extension UUID with a pref.
- **Seed script name.** POLISH_SPEC names `scripts/seed-polish.ts`; the entry is `scripts/seed-polish.mts` because the repo root is not an ES module package (like `scripts/generate-openapi.mts`). The implementation is `apps/web/e2e/seed-polish.ts` so the audit specs can import it.
